# RCA — Grades admin dashboard shows completed teachers as "not started / incomplete"

DB queried (read-only, PRODUCTION): `school-frontend-3-test_database`, active run `b80e5e25-f2f6-4c3a-91c5-16ef9200556e`.

## TL;DR — ROOT CAUSE
**Every single `grades_scores` document (163 of 163) has `quiz2 = null`.** The admin stats logic (`GET /api/grades/admin/stats`) counts a score as "completed" only when `quiz1 != null AND quiz2 != null`. Because no score anywhere has a non-null `quiz2`, the completed-count is **0 for every teacher**, so every teacher renders as "not started"/"incomplete" — regardless of how many grades they actually entered. The grade/section/subject/semester matching logic is NOT the problem (verified below — all formats match).

## Findings (concrete, per requested items)

### (1) grades_settings doc
Exactly 1 doc. Fields present:
- `grades_locked=false`, `parent_closed=true`, `site_closed=false`
- `subject_max` present with 10 subjects, e.g. `التربية الاسلامية` → `{quiz1:20, quiz2:10}`, all others `{quiz1:10, quiz2:10}`.
- **`current_semester` — ABSENT** → logic default `"1"` applies.
- **`grade_subject_max` — ABSENT**
- **`subjects_config` — ABSENT**

### (2) grades_scores totals
- Total: **163**
- `distinct(semester)` = **["1"]** (all match the default "1")
- `quiz2 == null`: **163 / 163** (100%). `quiz2` exists-and-non-null = 0; quiz2 field-missing = 0 → field is present but explicitly null in every doc.
- `quiz1 == null`: **1 / 163**

### (3) Orphan teacher_id (teacher_id not in grades_users ids)
- Only **3 distinct teacher_id** values appear in scores; all 3 exist in `grades_users` → **0 orphans**.
- BUT one of the three — `52a7b81d-e640-4cbb-aa3c-fcc07cd25655` ("مدير النظام") — is the **admin** account (`role=admin`, `assignments=[]`). Its 2 scores can never be attributed to any teacher row, since the admin loop iterates `role=teacher` only.

### (4) Assignments vs score values for the teachers that have scores
(Only 3 teacher_ids have scores; distribution 92 + 69 + 2 = 163.)

- **94317302** (أحمد — teacher): assignments = الخامس §1,§2,§3 / الرياضيات. Scores (92): subject `الرياضيات`, sections `["1","2","3"]`, grade الخامس. **Exact match.**
- **19944401** (ثاني — teacher): assignments = الثامن §1,§2 / الرياضيات. Scores (69): sections `["1","2"]`, grade الثامن, subject الرياضيات. **Exact match.**
- **52a7b81d** (مدير النظام — ADMIN, assignments=[]): 2 scores, grade الخامس §1, subjects التربية الاسلامية & الرياضيات. Not a teacher row → never counted.

**No mismatches found** in spelling/type/format:
- `grades_scores.section` distinct = `["1","2","3"]` — all **strings**.
- `grades_students.section` distinct = `["1".."7"]` — all **strings**. Same type/format → `str(section)==str(a.section)` holds.
- `grade` values (الثامن, الخامس) and `subject` values (الرياضيات, التربية الاسلامية) match assignment strings exactly. No Arabic-numeral (e.g. '٧/١') or int-vs-string discrepancy observed.

### (5) Teachers with empty assignments but with scores
- `role=teacher` AND `assignments` size 0: **0 teachers** have scores.
- The only empty-assignments id with scores is the **admin** account (see #3), not a teacher.

## Conclusion
The completion criterion `quiz2 != null` is the sole blocker. With 163/163 scores carrying `quiz2=null` — including teacher 94317302 who entered all 92 of his students across every assigned section — it is implausible that every teacher deliberately skipped quiz2. The likely causes (to be confirmed in source by E1):
1. The grade-entry **save path only persists `quiz1`** and leaves `quiz2` null (field written but never populated), OR
2. The **admin stats completion criterion is wrong** for this school's workflow (e.g. some subjects/period use only quiz1, or quiz2 is entered in a later flow), OR
3. quiz2 is captured under a different field/shape than what's persisted.

Secondary (non-blocking) note: grades_settings lacks `current_semester`, `grade_subject_max`, `subjects_config`; default "1" is consistent with all scores so it does not cause this symptom, but E1 should confirm these optional fields aren't expected elsewhere.

No data was modified. No deployment action taken.
